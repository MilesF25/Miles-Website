AGUMON, Making a LAN Server

Jul 12, 2026

A.G.U.M.O.N

Asynchronous Group User Messaging Over Networks

I built this project while studying for my CompTIA Security+ exam. As I learned more about databases and servers, I became more interested in the low-level side of cybersecurity. A SOC analyst needs to know how to use things like firewalls, but what really interested me was what the code behind them actually looks like. How does a firewall know what to block? How does a server handle multiple clients? This project was my attempt at understanding how servers are built and how they actually work. This project was hard. Diving into network programming with zero experience is not something I'd recommend. It is very different from regular programming, and trying to find resources on building a LAN server from scratch wasn't easy. On top of that, I was learning Rust features like `Arc`, `Mutex`, and multithreading at the same time. There were a lot of moments where I had to stop coding just to understand what was actually happening.

This project has 3 main parts, the host file, client file and the chatbot file. The main part, the host file. This file holds the server code. What it does is open port 5000, this is so only devices on the local network can access it. Then it generates a room following the room class i created. The room class has four attributes. Entry code, users, bot token and current number of bots. I wanted my server to have some securtiy so I made sure there is a way to control who can join and the amount of people that can join. Same concept for the bots. The main part of the code is the joining process, I used tokio to do asynchronous networking so multiple people can join at once and to make sure there are no issues if two people were to join at the same time i used Arc and Mutex which allows each process to access the same values safely. Lastly there is a validation check, the program can tell the difference between a chatbot and a real user and checks if there is space for them to join. The next important part is the client file. It could be argued that this file was just as hard as the host but what makes the host at lot harder is the fact i can't ask chatgpt to make me working server. The client handles the real humans connecting, sending and recieving messages to and from the server. The hard part was getting Ratatui to work. I was never good with ui.

Lastly the chatbot. Originally it was suppsoed to be a music bot but implemnting audio was too complex and even though it was part of the original idea, I did not properly set up my server from the start, trying to add it at the end was just too confusing so I decided not to. The chat bot is a good fall back, once the bot connects it will listen for when some has a question for it, example: "Gemini, how do you make cake" and it will respond.
