A.G.U.M.O.N

Asynchronous Group User Messaging Over Networks

Server Repo

I built this project while studying for my CompTIA Security+ exam. As I learned more about databases and servers, I became more interested in the lower-level side of cybersecurity. A SOC analyst needs to know how to use tools like firewalls, but what really interested me was understanding what the code behind them actually looks like. How does a firewall know what to block? How does a server handle multiple clients? This project was my attempt at understanding how servers are built and how they actually work. This project was hard. Diving into network programming with zero experience is not something I would recommend. It is very different from regular programming, and finding resources on building a LAN server from scratch was not easy. On top of that, I was learning Rust features like `Arc`, `Mutex`, and multithreading at the same time. There were many moments where I had to stop coding just to understand what was actually happening.

This project has three main parts: the host file, the client file, and the chatbot file. The main part is the host file. This file contains the server code. It opens port 5000, which allows only devices on the local network to access it. It then generates a room using the room class I created. The room class contains four attributes: an entry code, users, a bot token, and the current number of bots. I wanted my server to have some security features, so I made sure there was a way to control who could join and how many people could connect. The same concept applied to bots. The most important part of the code is the joining process. I used Tokio for asynchronous networking, allowing multiple people to join at the same time. To prevent issues when multiple users tried to join simultaneously, I used `Arc` and `Mutex` to safely share values between processes. Lastly, there is a validation check that allows the program to distinguish between a chatbot and a real user while also checking if there is enough space available.

The next important part is the client file. It could be argued that this file was just as challenging as the host, but what made the host harder was that I couldn't simply ask ChatGPT to create a working server for me. The client handles real users connecting and sending messages to and from the server. One of the hardest parts was getting Ratatui to work because UI development has never been my strongest area.

Overall, I am extremely proud of how this project turned out. It was one of the most challenging projects I have worked on, but it pushed me to learn concepts I had never worked with before. I started this project wanting to understand how servers work, and by the end, I had built something that gave me a much deeper appreciation for networking, cybersecurity, and low-level programming.
